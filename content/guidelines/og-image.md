This spec defines the share image (`og:image` and `twitter:image`) for every prerendered page on [sebastienbarbier.com](https://sebastienbarbier.com). Each page gets one 1200 by 630 PNG cover, generated at build time from the tokens in [brand.md](brand.md), with the page title and description set in the site's own type. A working prototype lives next to these guidelines in `og/` (see [Prototype](#prototype)).

Agents: load this file before changing share images, `updatePageSeo()` in `src/app/app.component.ts`, or route `data.shareImage`.

## How to use this file

- **Humans**: read the cover rules, then check the samples in `og/samples/`
- **Agents**: follow [Text limits](#text-limits) when writing route data and [Build integration](#build-integration) when wiring the generator
- **Siblings**: [writing.md](writing.md) for the copy on the image, [brand.md](brand.md) for tokens, [design.md](design.md) for the site layout

## Current state

Facts from the repo (`develop`):

- `updatePageSeo()` sets `og:type`, `og:site_name`, `og:title`, `og:description`, `og:url`, `og:image`, `og:image:width`, `og:image:height`, `og:image:type`, `og:image:alt`, `twitter:card` (`summary_large_image`), `twitter:title`, `twitter:description`, `twitter:image`, and `twitter:image:alt` on every navigation, and clears them on `/404`
- `og:image` comes from `OG_SHARE_MANIFEST` (generated by `scripts/generate-og-images.js` from route `data.og`), absolute URLs under `https://sebastienbarbier.com/og/<slug>.<hash>.png`
- Prerendered HTML gets the same tags from `scripts/postprocess-prerender-html.js` using `static/og-manifest.json`
- Light 1200 by 630 text-only covers for all prerendered routes except `/404`

## Goals

- One consistent, recognisable cover per page, so a shared link reads as Sébastien Barbier before anyone clicks
- Text that matches the page: the same facts as the route title and description
- Built from the brand kit only: palette tokens, Open Sans, Source Serif, the wordmark. No photos, no gradients
- Generated by a script in the build, so a new route gets a cover without design work

## Cover layout

All sizes in pixels on a 1200 by 630 canvas. The layout is a single left-aligned column.

| Element | Position and size | Type | Color (light / dark) |
| --- | --- | --- | --- |
| Canvas | 1200 by 630, 80 padding on all sides | | `#f8f5f2` / `#121110` |
| Wordmark | Top left at (80, 80), 320 by 40 | SVG paths from `sebastienbarbier_logo.svg` | `#202124` / `#e8eaed` |
| Eyebrow | Above the title, 16 below it to the title | Open Sans 600, 28 | `#865500` / `#d4a84b` |
| Title | Vertically centred block with eyebrow and description | Source Serif 600, 76 (title up to 28 characters) or 64, line height 1.15 | `#202124` / `#e8eaed` |
| Description | 24 below the title, max width 960 | Open Sans 400, 30, line height 1.45 | `#202124` / `#e8eaed` |
| Rule | Bottom left, baseline aligned with the domain | 120 by 2 | `#1f1d1d` / `#e8eaed` |
| Domain | 20 right of the rule, bottom edge at 550 | Open Sans 600, 26, `sebastienbarbier.com` | `#865500` / `#d4a84b` |

- The bottom rule and domain repeat the home hero's rule before the social icons, the one brand motif on the site
- Safe zone: keep all text inside the 80 px padding
- Contrast: eyebrow and domain gold reach 5.84:1 on light and 8.53:1 on dark; text reaches 14.82:1 and 15.65:1
- No images on the cover. **Open question**: an optional right-hand slot for a product screenshot on project pages

## Tokens

The generator copies these values from `src/assets/scss/_tokens.scss`. When a token changes there, change it in the generator in the same PR. **Open question**: read them from `_tokens.scss` automatically instead of copying.

| Generator key | Light | Dark | Source token |
| --- | --- | --- | --- |
| `background` | from SCSS | from SCSS | `--sys-color-background` |
| `text` | from SCSS | from SCSS | `--sys-color-on-background` |
| `accent` | from SCSS | from SCSS | `--sys-color-secondary` |
| `rule` | from SCSS | from SCSS | `--sys-color-primary` |

`scripts/generate-og-images.js` parses `_tokens.scss` at build time (no manual copy). Production covers use the light theme only.

Fonts: Open Sans 400 and 600 and Source Serif 4 600, static Latin WOFF files from `@fontsource/open-sans` and `@fontsource/source-serif-4` (Satori cannot read WOFF2 or variable fonts).

## Text limits

Limits keep every cover inside two title lines and three description lines. They were tested with worst-case strings in the prototype.

| Field | Limit | Default source | Rule |
| --- | --- | --- | --- |
| `eyebrow` | 40 characters | Page type ("Project", "Resume") or the role on home | Sentence case, no period |
| `title` | 40 characters, 2 lines | Route `data.title`; home uses the name | No period. Titles over 28 characters render at 64 px |
| `description` | 120 characters, 3 lines | Route `data.description` if 120 characters or shorter | One or two sentences. Facts only |

- Over the limit, the generator cuts at the last word boundary and adds `…`, and prints a warning. Treat a warning as a bug: write a shorter `og.description`, do not ship a truncated cover
- The generator warns on any em or en dash in the text; the build version should fail (see [writing.md](writing.md#punctuation-and-typography))
- 7 of the 11 route descriptions already fit in 120 characters. Home (182), resume (146), Shellui (139), and FromEdwin (121) need a shorter `og.description`

## Page data

Each prerendered route in `static.paths.txt` except `/404` gets a cover. The proposed route data shape:

```typescript
data: {
  title: 'Shellui',
  description: DESCRIPTION.shellui,
  shareImage: '/assets/og/projects-shellui.png',
  og: {
    eyebrow: 'Project',
    description: 'Open-source React and TypeScript microfrontend shell: unified auth, multi-tenant Django services, 1,000+ tests in CI.',
  },
}
```

- `slug`: the route path with slashes replaced by `-`, `home` for `/`. `/projects/shellui` becomes `projects-shellui`
- File: `/assets/og/<slug>.png`
- **Open question**: keep `og` inside route `data` (one source of truth, needs a parser like `scripts/generate-site-files.js` uses) or in a separate `src/og-pages.json` (simpler to read from Node, but a second place to edit)

## Generator approach

Build-time Satori plus sharp, as a Node script next to the existing scripts.

- **Satori** (`satori`) lays out a JSX-like tree with flexbox and real fonts and returns an SVG with text converted to paths. No browser and deterministic output. The prototype renders 3 covers in about 0.4 s, including startup
- **sharp** turns the SVG into a PNG. It is already a devDependency of the site (`sharp@^0.35.5`, used by `scripts/optimize-images.js`), so the only new dependencies are `satori` and the two `@fontsource` packages
- Why not Playwright: it needs a Chromium download in CI and is slower for 11 images, but it would render the real site CSS. Keep it as the fallback if covers ever need layout Satori cannot do
- Why not a runtime endpoint (`@vercel/og` and similar): the site is static on GitHub Pages, so there is no server to run it

### Build integration

1. Add `scripts/generate-og-images.js`, based on `og/generate-og-images.js`
2. Run it in `prebuild` after `generate-site-files.js`, so it sees the current route list: `"prebuild": "node scripts/sync-critical-shell.js && node scripts/generate-site-files.js && node scripts/generate-og-images.js"`
3. Write PNGs to `src/assets/og/`, which Angular copies to `dist/en/assets/og/`. **Open question**: commit the PNGs (reviewable in PRs, no build dependency) or add `src/assets/og/` to `.gitignore` (always fresh)
4. Set `shareImage: '/assets/og/<slug>.png'` on every route, replacing the screenshots and the portrait fallback
5. In `updatePageSeo()`, also set `og:image:width` `1200`, `og:image:height` `630`, `og:image:type` `image/png`, and `og:image:alt` (the cover title and eyebrow), plus `twitter:image:alt`
6. Fail the build if a prerendered route has no cover or if any text is over its limit

### Theme

- Ship the light cover. Link previews do not know the reader's theme, and the light canvas matches the site default
- The generator also renders a dark variant (`--theme dark`) for slides and dark backgrounds. **Open question**: publish dark covers anywhere, or keep them for manual use

### File budget

- PNG, 8-bit, `compressionLevel: 9`. The samples are 40 KB to 49 KB. Budget: 100 KB per cover
- Social platforms cache images by URL. **Open question**: add a content hash to the file name (`home.3f2a1c.png`) so updates show up without a manual cache refresh

## Prototype

The prototype is in `og/` beside `content/` in this drop (not in the site repo yet).

- `og/generate-og-images.js`: the generator (CommonJS, like the site's `scripts/`)
- `og/pages.json`: three sample pages
- `og/assets/sebastienbarbier_logo.svg`: copy of the wordmark, recolored per theme at render time
- `og/samples/`: `home.png`, `projects-shellui.png`, `resume.png`, and `.dark.png` versions

Run it:

```bash
cd og
npm install
node generate-og-images.js                 # light covers into samples/
node generate-og-images.js --theme dark    # dark covers
node generate-og-images.js --pages my-pages.json --out ../src/assets/og
```

The sample text comes from the site: the role and place in the home `<title>` and JSON-LD, the Shellui route description shortened to 117 characters, and the resume route description.

## Anti-patterns (flag these)

- Screenshots or the portrait used as `og:image` for a page that has a generated cover
- Covers with gradients, photos, emoji, or extra colors
- Text over the limits, or a truncated `…` cover in production
- Em or en dashes on a cover
- A cover whose title does not match the page `h1` or route title
- Missing `og:image:width`, `og:image:height`, or `og:image:alt`
- Tokens in the generator that differ from `_tokens.scss`
